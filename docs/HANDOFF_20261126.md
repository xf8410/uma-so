## 6. 遇到过的问题（全部实录，含根因与修法）

### 6.1 编译类

| 现象 | 根因 | 修法 |
|---|---|---|
| `E0308 mismatched types` at 10384 | `AtomicU64::store(usize)` 不接受 usize | `compressed as u64` |
| `E0425 cannot find AtomicUsize` | lib.rs 未导入 | 全限定 `std::sync::atomic::AtomicUsize` |
| `E0428 ORIG_UI_TEXT_PROLOGUE defined multiple times` | 我给 UI.Text 新建静态名与 TextCommon 的重名 | 改名 `ORIG_UNITY_UI_TEXT_PROLOGUE` |
| `failed to get umaai as dependency of matsuri-core` | umaai-next 是 submodule，clone 到该路径失败 | 用 `git submodule update --init --depth 1`，加 fallback |
| `default-features = false cannot override workspace's` | cargo 1.97 收紧规则 | CI 里 sed 去掉该覆盖 |
| workflow 名称显示为文件路径、无 job | YAML 里 `open_pr:{` 缺空格 | 补空格 |
| `git checkout` 128 | 工作区未跟踪文件冲突 | `git checkout -f` |
| `smudge filter lfs failed` | 上游 `reverse/` 目录走 LFS | `GIT_LFS_SKIP_SMUDGE=1` |
| Actions 存储配额满，artifact 传不上 | 1032 个 runs + 30 artifacts | 冲突报告改 commit 到 docs/conflicts/ |
| GitHub API PUT contents 连续 500 | 服务端波动 | 改用 Git Data API（blob→tree→commit→ref） |

### 6.2 运行期崩溃类

| 现象 | 根因 | 处理 |
|---|---|---|
| `signal 11, last_step "S:after_read_speed"` | 非育成态读已释放的 `Character`，读 `_speed`(248) 成功、`_stamina`(268) 崩 | 加 `_totalTurnNum(68)>0` 门禁（3 处）；**仍复现**，再加 chara_obj 类指针硬校验 |
| `F libc: Invalid address 0x... passed to free` | 堆损坏；怀疑 `il2cpp_string_new` 造的托管串未保 GC root | 中文串缓存 + `il2cpp_gchandle_new`（GPT 后指此不必要，已回退为每次新建） |
| hook `GetHighSpeedPlayDuration` 返回 0.05s，1~2 秒必崩 | 改的是所有消费者读到的时长，Timeline/物理换算炸掉 | 停用该 hook |
| `/scenario` 曾成功、后 `dataset_obj: null` | 崩溃后对象状态被重置 | 先修崩溃 |
| 加速倍率方案未验证 | — | 已全部停用 |

### 6.3 逻辑/结构类（都是"我以为"被实测推翻）

| 我的假设 | 实测 |
|---|---|
| `ParamsIncDecInfoArray` 长度在 `+0x10` | 实际 `+0x18`（+0x10 是 bounds/items） |

### 6.5 GPT 复核给出的关键纠正（务必遵守）

1. **安装时序**：一次性 `interceptor_hook` 无法保证 trampoline 就绪；必须由宿主保证"安装期间目标不可达"；`hook==true` 但 trampoline 查询失败 ≠ 安装失败
2. **移除写机器码兜底**：已删 `write_hook_bytes` fallback
3. **methodPointer 替换不是通用替代**：只影响经过该槽位的调用
4. **决策落点**：放在"候选已确定、尚未提交"处；策略只返回候选 ID；返回时校验 `revision`
5. **`ObscuredInt` 是 20 字节 struct**，不是 8 字节指针
6. **`5000` 方案有漏洞**：若所有训练都返回 5000，训练项之间仍按官方 add_value 排序；必须"选中 5000、其余 0"
7. **五处 hook 不够**：训练/休息/外出/比赛之间的**顶层命令选择**要单独接，且可能有硬分支
8. **最可能翻车是"结果过期/重复提交"**，不是分数不够 → 绑 `run_id + decision_seq + 候选版本`，提交前重校验，调用前标已消费
9. **第一步应先做全链路记录**（合法候选 → 原生选择 → 策略选择 → 实际提交 → 状态推进），再逐类接管；静默回退会让"全部接管"看起来已完成

## 9. 给接手者的话

1. **不要凭记忆写类名和偏移**。本轮所有错误都来自"我以为"。每个类先 `il2cpp/classes?keyword=` 确认存在，每个字段先 `dumpclass` 拿偏移，每个数组先读原始 hex 确认元素宽度。
2. **hook 成功 ≠ 生效**。零回调要先查"是不是绕过该槽位"，而不是继续改 hook 签名。
3. **崩溃优先查"时机"**，其次 ABI，最后才是数值。所有"1~2 秒崩"都是作用域/时机问题。
4. **决策落点选"候选已定、未提交"**，返回候选 ID 而不是改分数，除非确认分数会被最终采用。
5. 每改一次都留诊断端点（计数 + 原始字节 + 时间线），否则下一次崩溃又要从头猜。
